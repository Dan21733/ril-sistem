Alur Pendaftaran Device Otomatis — POS

Perangkat kasir mendaftar sendiri begitu terhubung ke jaringan toko yang di-whitelist. Token registrasi disisipkan di server jaringan toko (proxy dev), tidak pernah diketik atau dilihat manusia, dan tidak pernah masuk browser. 

%%{init: {"flowchart": {"curve": "basis", "htmlLabels": true}}}%%
flowchart TD
    subgraph DEVICE["PERANGKAT KASIR — browser POS"]
        A["Aplikasi kasir dibuka"]
        B{"Device sudah terdaftar
di penyimpanan lokal?"}
        C{"Ada koneksi
ke server toko?"}
        WAIT["Tunggu koneksi.
Otomatis mencoba lagi begitu online"]
        ASK["Minta pendaftaran otomatis
lewat jaringan toko"]
        FAIL["Tampilkan alasan gagal
+ tombol Coba Lagi"]
        DONE["Device siap dipakai:
punya kode nota T01–T99 dan token rahasia"]
    end

    subgraph PROXY["JARINGAN TOKO — whitelist pemilik"]
        INJECT["Menyisipkan tanda pengenal toko
(token registrasi, rahasia,
tidak pernah sampai ke browser)"]
    end

    subgraph SERVER["SERVER TOKO"]
        VAL{"Tanda pengenal valid?"}
        NEW["Buat device baru:
pilih kode nota kosong (T01…T99)
+ kunci penomoran nota"]
        TOK["Terbitkan token rahasia
(berlaku 30 hari)"]
        SAVE["Simpan identitas device
di penyimpanan lokal perangkat"]
        RETRY["Registrasi ulang otomatis
saat token kedaluwarsa (30 hari)"]
    end

    A --> B
    B -- "Ya" --> DONE
    B -- "Belum" --> C
    C -- "Tidak" --> WAIT
    WAIT -- "Koneksi kembali" --> ASK
    C -- "Ya" --> ASK
    ASK --> INJECT
    INJECT --> VAL
    VAL -- "Tidak valid" --> FAIL
    VAL -- "Valid" --> NEW
    NEW --> TOK
    TOK --> SAVE
    SAVE --> DONE
    FAIL -- "Kasir klik Coba Lagi" --> ASK
    DONE -.->|"Token kadaluwarsa
setelah 30 hari"| RETRY
    RETRY --> ASK
